# Приёмка дизайна

Пройти перед тем, как считать макеты готовыми и вставлять скриншоты
в презентацию. Занимает 15 минут, спасает от потери баллов в разделе
«Ясность» (5) и «Удобство использования» (5).

## 1. Единство

- [ ] Все экраны в одной палитре — открыть шесть PNG рядом и посмотреть
- [ ] Один набор иконок, одна толщина обводки
- [ ] Одинаковая ширина левой панели и высота верхней на всех экранах
- [ ] Одна тень, нигде не появилось второй
- [ ] Нет градиентов, стекла, скруглений больше 8 px
- [ ] Радиусы одинаковые: 8 карточки, 6 кнопки, 4 чипы

## 2. Тексты

- [ ] Каждая строка на экранах есть в `05-copy-ru.md`
- [ ] Ничего не переведено на английский и не придумано моделью
- [ ] Десятичный разделитель — запятая, везде
- [ ] Единицы через пробел: «96,2 га», «26,4 °C»
- [ ] Минус типографский (−), не дефис
- [ ] Опечаток нет — прочитать вслух каждую подпись
- [ ] Кнопки — инфинитив, заголовки — существительное

## 3. Данные на макете

- [ ] Карта — серая заглушка с сеткой, без выдуманной спутниковой подложки
- [ ] На карте есть «© OpenStreetMap contributors»
- [ ] Кривая NDVI похожа на настоящую фенологию: рост, пик, спад
- [ ] Ось Y графика от 0,0 до 1,0
- [ ] Нет графика с двумя осями Y
- [ ] Легенда присутствует и включает формы маркеров
- [ ] Восстановленные значения отличаются пунктиром, а не только цветом
- [ ] Числа правдоподобны: NDVI в диапазоне 0…1, площади в сотнях гектаров,
      осадки в миллиметрах

## 4. Читаемость

- [ ] Нигде нет текста меньше 12 px
- [ ] Контраст основного текста к фону не ниже 4,5:1
- [ ] Открыть PNG на 50 % масштаба — заголовки и значения всё ещё читаются
- [ ] Перевести PNG в оттенки серого — статусы всё ещё различимы
      (если нет, значит цвет несёт смысл в одиночку — чинить)

## 5. Полнота

- [ ] Все шесть основных экранов есть
- [ ] Есть минимум четыре состояния: пусто, загрузка, нет данных,
      часть источников недоступна
- [ ] Ни один экран не даёт «белого поля» — везде что-то показано
- [ ] Экран сбора данных показывает названия этапов дословно из `05-copy-ru.md`
- [ ] Карточка аномалии содержит цифры, а не общие слова

## 6. Готовность к сдаче

- [ ] PNG всех экранов в `docs/screenshots/`, имена `<ID>-<краткое-имя>.png`
- [ ] Экспорт в Figma сделан, ссылка записана в `07-handoff.md`
- [ ] Финальный стиль-блок зафиксирован в `02-style-block.md`
      и совпадает с тем, чем реально генерировали
- [ ] Скриншоты для презентации сняты из **живого продукта**, а не из макета

## Про последний пункт отдельно

Макеты Stitch — это то, по чему строится интерфейс. **В презентацию идут
скриншоты работающего сервиса**, а не макеты.

Причина простая: на защите будет живое демо. Если слайд показывает
вылизанный макет, а демо — реальный продукт, разница видна мгновенно,
и весь слайд начинает читаться как обещание вместо результата. Реальный
интерфейс, сделанный по хорошему макету, выигрывает у самого макета.

Макеты уместны только в одном месте — в отчёте, в разделе про процесс,
с подписью «проектирование интерфейса». Там это плюс.

## Типовые провалы, которые ловит этот список

| Что происходит | Чем кончается |
|---|---|
| Стиль-блок поправили посреди работы | Три экрана в одной палитре, три в другой |
| Модель перевела подписи на английский | Скриншот в презентации не совпадает с демо |
| Нарисована красивая спутниковая карта | В демо серые тайлы OSM, эксперт замечает |
| График с двумя осями Y | Вопрос на защите, на который нет хорошего ответа |
| Состояния не нарисованы | В демо белый экран на первой же ошибке |
| Текст 10 px «чтобы влезло» | Минус балл за ясность, ничего не видно с проектора |
