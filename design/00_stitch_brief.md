# Работа с Google Stitch: что он умеет и чего от него не ждать

Stitch — это генератор экранов по текстовому промпту, а не среда проектирования.
Он отдаёт картинку, Figma-слои и HTML/CSS. **Мы берём из него только визуал:**
макеты, палитру в деле, композицию, состояния. Код продукта пишут дев-агенты
по `docs/06-frontend/` — из Stitch в репозиторий не переносится ни строчки.

## Что важно знать до первого промпта

| Факт | Что из этого следует для нас |
|---|---|
| Два режима: **Standard** (Gemini 2.5 Flash) и **Experimental** (Gemini 2.5 Pro, принимает картинки) | Черновики гоним в Standard, финальные экраны — в Experimental |
| Лимиты: **350 генераций/мес Standard, 50/мес Experimental** | Experimental — дефицитный ресурс. Бюджет ниже |
| **Нет управления дизайн-системой.** Нельзя завести токены, компоненты, бренд-гайд | Главная проблема. Решение — «стиль-блок», который вставляется в начало **каждого** промпта. См. `02-style-block.md` |
| Есть ручная правка на холсте: текст, замена картинок, отступы | Мелочи правим руками, а не новой генерацией. Экономит лимит |
| Есть связывание экранов в прототип и генерация «логичного следующего экрана» | Пользуемся для флоу «регион → контуры → анализ» |
| Экспорт в Figma с Auto Layout и именованными слоями | Оттуда берём точные отступы и размеры для дев-агентов |
| **Нет анимаций и микровзаимодействий** | Все состояния (загрузка, ховер, прогресс) описываем **отдельными статичными экранами**, а поведение — текстом в `07-handoff.md` |
| Однопользовательский, без комментариев и истории версий | Версии храним сами: экспорт PNG в `docs/screenshots/` с датой в имени |

## Бюджет генераций

Считаем на один полный проход. Итераций обычно две-три, поэтому закладываем запас.

| Что | Режим | Генераций |
|---|---|---|
| Калибровка стиля (подбор палитры на одном экране) | Standard | 6–10 |
| 6 основных экранов, черновик | Standard | 12–18 |
| 8 состояний (пусто, загрузка, ошибки, частичные данные) | Standard | 10–16 |
| 6 основных экранов, финал | **Experimental** | 12–18 |
| Ключевой экран (результат анализа) — доводка | **Experimental** | 6–10 |
| **Итого** | | ~40–70 Standard, ~20–28 Experimental |

Влезает в месячный лимит с запасом, но не с бесконечным. Правило: **если правка
не про композицию — правь руками на холсте, а не промптом.**

## Порядок работы

```
1. Калибровка стиля
   Берём ОДИН экран (S-03 «Результат анализа») и на нём подбираем стиль-блок,
   пока картинка не станет такой, какую хочется видеть везде.
   Зафиксировать финальный стиль-блок в 02-style-block.md, дальше не менять.

2. Черновики всех экранов в Standard
   Каждый промпт = стиль-блок + описание экрана из 03-prompts.md.
   Цель — проверить, что композиция работает, а не красота.

3. Состояния
   Пустое, загрузка, нет данных, часть источников недоступна, мало истории.
   Это отдельные экраны, а не варианты. Список — в 04-screens-states.md.

4. Финал в Experimental
   Те же промпты, режим Experimental. При необходимости подгружаем
   картинку удачного черновика как референс.

5. Ручная доводка на холсте
   Тексты — строго из 05-copy-ru.md. Отступы, выравнивание, замена подписей.

6. Экспорт
   PNG всех экранов в docs/screenshots/ + Figma-файл.
   Ссылки на них — в 07-handoff.md, дев-агенты работают по ним.
```

## Язык промптов

**Промпты пишем по-английски, тексты интерфейса вставляем по-русски в кавычках.**
Модель понимает английские инструкции точнее, но подписи кнопок обязана взять
дословно те, что даны. Формулировка, которая работает:

```
All UI copy must be in Russian, use exactly these strings, do not translate
or invent labels: "Найти поля", "Анализировать", "Мои полигоны".
```

Если оставить это на усмотрение модели, она напишет «Analyze» или переведёт
по-своему, и экраны разъедутся с реальным интерфейсом.

## Правила, которые экономят время

1. **Один промпт — один экран.** «Сделай приложение» даёт кашу.
2. **Стиль-блок дословно, без сокращений, в начале каждого промпта.**
   Дизайн-системы у Stitch нет; единственный способ удержать единый вид —
   повторять описание стиля каждый раз одинаково.
3. **Никогда не просить нарисовать «график NDVI» или «карту» как настоящие.**
   Модель нарисует правдоподобную ложь. Как формулировать — `06-charts-and-map.md`.
4. **Не менять стиль-блок посреди работы.** Изменил — переделывай все экраны,
   иначе половина будет в старом виде.
5. **Сохранять удачный промпт целиком.** Промпт — это исходник; экран — сборка.
