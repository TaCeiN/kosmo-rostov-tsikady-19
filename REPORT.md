# Исследовательский отчёт

Восстановление ряда `primary_ndvi` (задача 1) и детекция негативных аномальных
периодов вегетации (задача 2).

Запуск решения и структура репозитория — [README.md](README.md). Здесь только
ход работы: что видели в данных, что из этого следовало, что проверяли и чем
это кончилось.

---

## 1. Задача и протокол оценки

Задача 1 оценивается автоматически. По контрольным строкам
(`is_synthetic_gap = True`) считается RMSE между скрытым `primary_ndvi_true` и
предсказанием, затем переводится в GapScore:

```
GapScore = round(30 * max(0, 1 - RMSE / 0.10), 2)
```

Порог 0.10 соответствует качеству простейшего baseline — усреднения двух
ближайших известных значений. **Метрика линейна по RMSE: каждая тысячная RMSE
стоит 0.3 балла из 30.** Это определило всю дальнейшую тактику — гнаться имело
смысл только за изменениями порядка 0.001 и выше, всё мельче тонет в шуме.

Задача 2 автоматической метрики не имеет: разметки аномалий в тесте нет.
Оценивали её косвенно — согласием классов, посчитанных по восстановленному
значению и по фактическому, на своих синтетических дырках.

## 2. EDA: что в данных

`train_dataset.csv` — 99 955 строк, 39 полигонов, сезоны 2010–2024,
1 апреля — 30 октября суточной сеткой (213 суток в году).

**Ряд дырявый на две трети.** `primary_ndvi` заполнен в 30 520 строках из
99 955 — это 30.5 %. Остальное выбито облачностью.

| сенсор | доля строк с наблюдением |
|---|---|
| Landsat | 15.6 % |
| Sentinel-2 | 11.2 % |
| MODIS | 7.5 % |

**Пропуски идут сериями, а не поодиночке.** 16 439 серий, медиана 3 суток,
p90 — 8 суток, максимум 36. В серии длиной до 3 суток попадает лишь 22 % всех
пропущенных дней: основная масса — это длинные окна.

> **Решение из этого наблюдения.** Валидационные дырки нельзя ставить случайными
> одиночными точками — так задача становится заметно легче реальной.
> `validation.sample_gaps_fast` прячет наблюдения сериями по 1–4 подряд, имитируя
> облачность.

**Культуры перекошены.** Озимая пшеница 52 787 строк, зерновые 27 119,
подсолнечник 15 975, пастбища/зерновые 4 074. Пшеница задаёт и основную ошибку:
у неё резкий весенний пик, который легко промазать.

**Устройство теста важнее устройства train.** В первом тесте 3112 контрольных
точек, из них 2648 (85 %) — на полигонах, которых в обучении не было вообще.

> **Решение.** Валидация со случайным сплитом врёт в оптимистичную сторону.
> Основной сценарий — `scenario_new_polygon`: GroupKFold по полигонам,
> валидационные поля целиком вне обучения.

**Что видно в самой контрольной строке.** Замаскировано всё, кроме
`anon_polygon_id`, `date`, `is_synthetic_gap`, `crop_type`: нет спутниковых
индексов, нет ERA5, нет климатнормы, нет `doy`/`year` (восстанавливаются из даты).

> **Решение, определившее архитектуру кода.** Признаки считаются **только по
> замаскированной копии** (`ndvi_ml.data.mask_rows`). Любой признак, читающий
> колонки самой целевой строки, — утечка, которая не воспроизведётся на
> приватном скоре. На это есть тест: `ml/tests/test_no_leakage.py`.

## 3. Данные: что использовали и почему

**Основа — наборы организаторов.** `train_dataset.csv` для обучения,
`test1_features.csv` + выданный к нему `private_test_ground_truth.csv` для
честного замера, `test_features.csv` — текущий тест.

**Ответы на первый тест превратились в обучающие данные.** `prepare_labeled.py`
сшивает 3112 раскрытых значений с признаками, размеченная выборка растёт с
30 520 до 64 437 наблюдений — вдвое. Подключается флагом `--extra labeled_test1.csv`.

**Дособранные полигоны через Google Earth Engine.** Постановка это прямо
разрешает, а 78 полей для обобщения на новые территории мало.
`data_collection/` содержит рецепт данных организаторов, восстановленный из
самих данных (`RECIPE.md`), и скрипты сбора: OSM Overpass для контуров, GEE для
Sentinel-2 / Landsat / MODIS / ERA5, сведение в их схему и сверку распределений.

Ключевое из рецепта: `primary_ndvi` = S2, иначе Landsat, иначе MODIS. Проверено
на 2308 строках, где есть и S2, и Landsat, — S2 побеждает всегда. NDWI считается
по формуле Макфитерса через зелёный канал, ERA5 — среднесуточная температура и
суточная сумма осадков.

Дособранные данные **никогда не попадают в валидацию**: строки помечены
`source == "external"` и исключаются во всех трёх сценариях. Иначе метрика
перестала бы быть сравнимой с платформенной.

## 4. Baseline и его ограничения

Точка отсчёта — **линейная интерполяция** между ближайшими известными точками.
Ровно она задаёт порог 0.10 в формуле GapScore.

Компоненты её пайплайна элементарны: отсортировать ряд полигона по датам, для
каждой дырки взять ближайшее наблюдение слева и справа, интерполировать по
времени. Реализация — `ndvi_ml/baselines.py::predict_linear`.

Что она делает хорошо: короткие дырки. На пропусках 1–3 суток её RMSE 0.0657
против 0.0428 у финальной модели — разрыв всего в полтора раза.

**Где она ломается:**

| длина пропуска | линейная | модель | разрыв |
|---|---|---|---|
| 1–3 сут | 0.0657 | 0.0428 | −35 % |
| 4–7 сут | 0.0701 | 0.0426 | −39 % |
| 8–16 сут | 0.1013 | 0.0762 | −25 % |
| 17–31 сут | 0.0946 | 0.0686 | −27 % |
| >31 сут | 0.1083 | 0.0765 | −29 % |

Причина понятна: линия не знает формы сезонной кривой. На длинном окне она
режет весенний пик пшеницы прямой, теряя половину амплитуды.

**Гипотезы, которые из этого следовали:**

1. Дать модели форму сезона — климатнорму по тому же полигону и той же фазе.
2. Дать альтернативные измерения той же величины — NDVI других сенсоров.
3. Дать причину отклонения — погоду ERA5.
4. Не выводить кривую с нуля, а поправлять классические сглаживатели, подавая
   их предсказания как признаки.

## 5. Финальный подход

**Стекинг сглаживателей.** Savitzky-Golay, Whittaker (λ = 5, 30, 200) и
«климатнорма + аномалия» считаются по тем же видимым точкам, что и остальные
признаки, и подаются в LightGBM как обычные колонки. Утечки нет, а модели проще
исправлять систематическую ошибку сглаживателя, чем выводить форму кривой с нуля.

**Обучающие примеры — это тоже дырки.** В каждом раунде прячем случайные 15 %
наблюдений сериями по 1–4, считаем признаки по замаскированной копии и берём в
обучение **только спрятанные строки**. Несколько раундов = аугментация. Так
распределение признаков на обучении совпадает с тем, что модель увидит на
контрольных точках. Это главное архитектурное решение всего пайплайна.

**Климатнорма — leave-one-year-out.** Иначе норма подсматривает в тот самый
сезон, который восстанавливаем. Статистики сезона и полигона — leave-one-out по
той же причине: у видимых строк они иначе включают собственный NDVI, а у скрытых
нет, и обучение расходится с инференсом.

Финальная конфигурация записана прямо в артефакте
(`ml/artifacts/ndvi_model.pkl`):

```
target: raw            учим сам NDVI, а не поправку к сглаживателю
clip:   (-0.02, 0.93)  границы реальной разметки организаторов
rounds: 20             раундов маскирования
seeds:  [0, 42, 100]   ансамбль LightGBM + CatBoost
features: 107
```

Гиперпараметры LightGBM: `learning_rate 0.02`, `num_leaves 63`,
`min_data_in_leaf 25`, `feature_fraction 0.75`, `bagging_fraction 0.8`,
`lambda_l2 1.0`, 2500 деревьев. Веса примеров: ×1.4 на озимой пшенице, ×1.25 на
фазе весеннего отрастания (DOY 90–160) — там сосредоточена основная ошибка.

## 6. Эксперименты

Полный журнал ночного прогона — [ml/reports/NIGHT_LOG.md](ml/reports/NIGHT_LOG.md)
(50 конфигураций). Сравнивать между собой можно только конфигурации на одном
кэше признаков: у разных версий набор признаков и объём выборки различаются.

### Что дало прирост

**1. Пространственный сигнал по датам (+0.0016).** Для каждой даты считается
средняя аномалия ДРУГИХ полигонов относительно их собственной нормы. Поля лежат
в одном регионе и переживают одну погоду, поэтому просадка у соседей в этот
день — прямая улика. Своя строка из среднего исключается. Абляция без группы:
0.07657 → 0.07814.

**2. Объём обучающей выборки — главный рычаг.** Примеры генерируются
маскированием, их количество ограничено только временем:

| раундов | примеров | RMSE |
|---|---|---|
| 9 | ~48 000 | 0.07595 |
| 15 | ~80 000 | 0.07541 |
| 25 | ~133 000 | 0.07490 |
| 40 | ~213 000 | 0.07452 |

Отдача затухает, но за ночь не кончилась ни разу — единственный рычаг с таким
поведением.

**3. Медленное обучение.** `learning_rate` 0.04 → 0.02 при 2500 деревьях даёт
−0.0004. Мелочь, но воспроизводится на всех фолдах.

### Абляции: что несёт сигнал

RMSE при удалении группы признаков, опора 0.07657:

| убрано | RMSE | вклад |
|---|---|---|
| кросс-сенсорные (S2/Landsat/MODIS) | 0.07866 | **+0.0021** |
| пространственные по датам | 0.07814 | **+0.0016** |
| погодные (ERA5) | 0.07693 | +0.0004 |
| сглаживатели | 0.07652 | ≈ 0 |
| годы-аналоги | 0.07656 | ≈ 0 |
| гармоники | 0.07632 | −0.0003 (мешают) |

Сглаживатели за ночь потеряли роль: раньше давали 67 % прироста, теперь их
вклад перекрыт пространственными признаками. В наборе оставлены — вреда нет, а
на коротких дырках они всё ещё лучшая опора.

### Что не сработало

| гипотеза | результат | почему, скорее всего |
|---|---|---|
| годы-аналоги (похожие сезоны того же поля) | 0.00000 | сигнал уже покрыт климатнормой и пространственными признаками |
| гармоническая подгонка сезона | вредит −0.0003 | период гармоник — год, а сезон 213 суток: подгонка неустойчива на краях |
| учить поправку к сглаживателю вместо NDVI | +0.0009 хуже | модель и так получает сглаживатели как признаки |
| отдельная модель под длинные дырки | +0.0013 хуже | дробление выборки дороже специализации |
| веса примеров по длине пропуска | +0.0005 хуже | искажает распределение, под которое калибруется модель |
| устойчивые лоссы (huber, fair, MAE) | ±0.0002 | шум; MAE лучше по MAE, но хуже по RMSE — а оценивают по RMSE |

### Дособранные данные: A/B на честном холдауте

78 полигонов разделили пополам: 38 в обучение (A), 40 в холдаут (B).
Затем к обучению A добавили 31 950 дособранных строк по 10 своим полигонам.

| вариант | n | RMSE | GapScore | ±0.05 |
|---|---|---|---|---|
| control (только A) | 1279 | 0.06663 | 10.01 | 74.59 % |
| augmented (A + внешние) | 1279 | 0.06686 | 9.94 | 74.51 % |

**Вывод: прироста нет, ΔRMSE +0.00023 — в пределах шума.** Гипотеза «больше
полигонов = лучше обобщение» на этом объёме не подтвердилась. Инфраструктура
сбора осталась в репозитории: рычаг рабочий, но требует не 10 полигонов, а
порядок больше. Лог — `ml/extra_ab.log`, срезы — `ml/reports_halfsplit/`.

### Про потолок измеримости

3 строки из 7222 имеют физически невозможный NDVI (вне [−1, 1]) и дают 19 % MSE.
Без них RMSE модели 0.0658 против 0.0749. Это не наша ошибка: в ground truth
организаторов эти значения такие же.

> **Практический вывод.** Улучшения меньше 0.0005 в среднем по фолдам не
> измеримы. Ориентировались на `RMSE_clean` и на то, выигрывает ли конфигурация
> на всех четырёх фолдах сразу.

Оправдалось: локальная валидация предсказывала RMSE 0.0745, а `RMSE_clean`
давала 0.0651. На реальных ответах вышло **0.06384** — почти точное попадание
в `RMSE_clean`.

## 8. Задача 2: детекция аномалий

**Логика.** z-score считается относительно климатнормы того же полигона и той
же фазы сезона, норма — leave-one-year-out:

```
z = (NDVI_факт − NDVI_клим_среднее) / NDVI_клим_std
```

Пороги взяты из постановки: z ≥ −1 штатное развитие, −2 ≤ z < −1 угнетение
биомассы, z < −2 критическая аномалия.

**Два решения поверх порогов:**

1. **z считается по сглаженному ряду, а не по восстановленному напрямую.**
   `anomalies.smooth_filled` — Whittaker λ=20 с весом 0.25 на восстановленных
   точках: им доверия меньше, чем наблюдениям. Без этого одиночные выбросы дают
   ложные срабатывания.
2. **Период засчитывается от 10 суток подряд.** Короче — это облако или шум,
   а не угнетение вегетации.

**Интерпретация причины** подбирается по ERA5 вокруг периода: дефицит осадков,
температурный стресс, засуха (оба сразу) либо «устойчивое угнетение без явного
погодного сигнала» — последнее прямо указывает на агрооперацию или ошибку
данных, и это ценный сигнал, а не отказ.

**Качество** (согласие классов на восстановленных значениях против фактических,
7222 точки):

| | наша модель | линейная интерполяция |
|---|---|---|
| точность класса | 91.1 % | 85.3 % |
| RMSE самого z | 0.652 | 0.880 |
| recall аномалий | 65.8 % | 49.9 % |

Восстановление ряда напрямую улучшает задачу 2: recall вырос в 1.3 раза
относительно линейной опоры.

**Примеры найденных случаев** (`ml/artifacts/anomalies.csv`, 782 периода на 78
полях; 20 полей чистые — пустое состояние важно и оно есть):

| полигон | период | сут | z_min | причина |
|---|---|---|---|---|
| AOI-0022 | 2013-10-01 … 10-17 | 17 | −10.78 | краткое отклонение, погодой не объясняется |
| AOI-0004 | 2010-04-01 … 07-07 | 98 | −5.35 | устойчивое угнетение без погодного сигнала |
| AOI-0017 | 2024-05-06 … 10-30 | 178 | −4.52 | устойчивое угнетение без погодного сигнала |

Первый случай — нетривиальный: глубина −10.78σ за 17 суток при нормальной
погоде. Так выглядит не засуха, а уборка или ошибка данных. Разделение
«погодное / не погодное» здесь и работает.

Распределение причин по всем 782 периодам: дефицит осадков 114, засуха 46,
температурный стресс 29, остальное — без явного погодного сигнала.

## 9. Ограничения и куда копать

* **Recall аномалий 66 %.** Треть реальных просадок уходит в штатное развитие.
  Порог по z — сознательно простое решение: разметки аномалий в тесте нет,
  обучать классификатор не на чем. Следующий шаг — квантильная регрессия для
  доверительного коридора вместо жёсткого порога.
* **Одно поле за раз.** Пространственные признаки — вторая по силе группа, но
  для одиночной области они пусты, и точность ниже эталонной. Это ожидаемо, а
  не поломка; в интерфейсе такой запрос честно помечается.
* **Минимум 3 сезона.** Климатнорма leave-one-year-out на одном сезоне пуста:
  ряд восстановится, аномалии не найдутся. `/analyze` следит за этим сам.
* **Регион обучения.** Расчёт разрешён везде, но климатнорма и разбор причин
  откалиброваны на Ростовской области — ответ помечается `outside_region`.
* **`rounds` больше 40** — отдача не кончилась, ветка живая.
* **Дособор полигонов** — на 10 полигонах прироста нет, нужен порядок больше.

## 10. Воспроизводимость

```bash
cd ml

# честный замер на ответах организаторов -> reports_truth/
python evaluate_truth.py --train train_dataset.csv \
    --test-features test1_features.csv \
    --truth private_test_ground_truth.csv --rounds 15

# ответы -> обучающие данные
python prepare_labeled.py --features test1_features.csv \
    --truth private_test_ground_truth.csv --out labeled_test1.csv

# валидация и сравнение методов -> reports/
python run_experiment.py --train train_dataset.csv --test test_features.csv \
    --folds 4 --rounds 15 --outdir reports

# финальная модель и сабмит -> artifacts/
python predict_submission.py --train train_dataset.csv --test test_features.csv \
    --extra labeled_test1.csv --rounds 20 --seeds 0,42,100 --outdir artifacts
```

Всё детерминировано: `seed` фиксирован (`0` базовый, `0,42,100` для ансамбля),
маскирование идёт от `numpy.random.default_rng(seed)`, порядок строк
нормализуется сортировкой по `(anon_polygon_id, date)`.

Версии зависимостей — `ml/requirements.txt` и `backend/requirements.txt`.
Ночная лаборатория (`ml/night/`) кэширует матрицы признаков в `cache_*/`:
пересчёт занимает 90 % времени прогона, поэтому эксперименты работают по кэшу и
занимают минуты вместо получаса. Сравнивать конфигурации между собой можно
только на одном кэше.
