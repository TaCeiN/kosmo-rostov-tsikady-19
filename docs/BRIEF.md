# Исходный бриф на веб-часть

Здесь сохранено исходное техническое задание. Документация
работающего решения — в [README.md](README.md).

Папка самодостаточна. Внутри — рабочий бэкенд, посчитанные данные и контракт API.
Ничего из основного репозитория докачивать не надо.

## Что за проект

Спутники снимают поля, из снимков считается NDVI — индекс зелёности. Ряд
дырявый: облака выбивают до 70% суток. Модель восстанавливает пропуски и по
восстановленному ряду находит периоды угнетения вегетации с погодным
объяснением.

Модель обучена, метрики посчитаны, ML трогать не нужно. Нужен интерфейс.

Качество на реальных ответах организаторов: RMSE 0.064, R² 0.91, 74%
предсказаний в пределах ±0.05. Линейная интерполяция для сравнения — 0.097.

## Главная цепочка

```
человек обводит поле на карте
        v
POST /analyze  {geometry, years}         -> job_id  (мгновенно)
        v
бэкенд тянет Sentinel-2, Landsat, MODIS и погоду ERA5 из Google Earth Engine
        v
модель восстанавливает суточный ряд и ищет аномалии
        v
GET /analyze/{job_id}  -> ряд, аномалии с причинами, сводка
        v
человек видит график и разбор
```

**Замерено на живом поле 6.2 га за 10 сезонов:** выгрузка 57 с, модель 0.6 с,
на выходе 2130 суток, 728 наблюдений (34% покрытия), 7 аномальных периодов,
ответ 0.9 МБ. Это не оценка — `samples/analyze_response.json` и есть результат
того самого вызова.

Минута — это долго. Поэтому запрос оформлен задачей: `POST /analyze` отдаёт
`job_id` сразу, фронт опрашивает `GET /analyze/{job_id}` раз в 2–3 секунды и
показывает `stage` и `progress`. Держать открытым HTTP-запрос на минуту нельзя,
браузер и прокси его оборвут.

## Что построить

**1. Карта.** Leaflet + OpenStreetMap, без ключей. Инструмент рисования
прямоугольника или полигона. Рисование ограничить рамкой из `GET /meta` —
модель обучена на Ростовской области, за её пределами ответ будет уверенной
чепухой, и бэкенд такой запрос отклонит с 400. Выбор диапазона лет и культуры
из справочников `/meta`.

**2. Прогресс.** После отправки — опрос задачи, показ стадии. Стадии две:
«тянем спутники и погоду» и «считаем признаки и восстанавливаем ряд».

**3. Разбор.** График: точки наблюдений, восстановленная кривая, климатнорма
с коридором ±1σ, подсветка аномальных периодов. Под ним карточки аномалий:
даты, длительность, глубина просадки, причина. Сбоку сводка: сколько суток,
сколько наблюдений, по каким сенсорам, покрытие.

**4. Демо-режим.** 78 готовых полигонов из `data/`, без обращения к бэкенду.
Нужен: GEE может быть не настроен, а показывать что-то надо всегда. Это же
экран «качество модели» — метрики и разрезы лежат в `data/metrics.json`.

Стек на твоё усмотрение.

## Запуск бэкенда

```bash
cd backend
pip install -r requirements.txt
uvicorn serve:app --reload --port 8000
curl http://localhost:8000/health
```

Для `/analyze` нужен доступ к Earth Engine — см. «Доступы» ниже. Без него
`/meta` вернёт `"gee_available": false`, а `/analyze` — 503 с понятным текстом.
Всё остальное работает.

Контракт — `API.md`. Машинное описание — `openapi.json`, сгенерировано из
самого приложения. Живой обмен — `samples/`.

## Доступы: Google Earth Engine

Ключей в этой папке нет и быть не должно. Заводи на свой аккаунт.

1. Зарегистрировать Cloud-проект в Earth Engine:
   https://code.earthengine.google.com/register (для некоммерческого
   использования бесплатно).
2. Для разработки хватит пользовательских кред:
   ```bash
   pip install earthengine-api
   earthengine authenticate
   export GEE_PROJECT=твой-project-id
   ```
3. Для деплоя — сервисный аккаунт, он не привязан к живому человеку и не
   протухает:
   - Google Cloud Console → IAM → Service Accounts → создать;
   - выдать роль **Earth Engine Resource Viewer**;
   - зарегистрировать его почту в Earth Engine как пользователя проекта;
   - скачать JSON-ключ, положить вне репозитория;
   ```bash
   export GEE_SERVICE_ACCOUNT_KEY=/secure/path/key.json
   export GEE_PROJECT=твой-project-id
   ```

Проверка: `curl localhost:8000/meta` → `"gee_available": true`.

Шаблон переменных — `.env.example`. Реальные значения туда не коммить,
`.env` уже в `.gitignore`.

**Карта работает без всяких ключей**: Leaflet + OpenStreetMap. Google Maps
потребует отдельный ключ и не даст ничего, чего нет у OSM.

## Готовые данные: `data/`

78 полигонов организаторов, уже посчитанные. Бэкенд для них не нужен —
статика, фронт работает на файлах.

| файл | что |
|---|---|
| `meta.json` | список полигонов с культурой, годами, счётчиками; словари значений |
| `series/<id>.json` | суточный ряд одного полигона за 2010–2025 |
| `anomalies.json` | все 782 аномальных периода |
| `metrics.json` | метрики модели и разрезы |

Не путать с `GET /meta` у бэкенда: это разные вещи, одноимённые по случайности.
`data/meta.json` — про 78 готовых полигонов, `GET /meta` — про лимиты сервиса.

### `series/<id>.json`

**Параллельные массивы, не список объектов.** Все массивы одной длины, индекс
общий. Объектами это вчетверо жирнее, и переключение полигона тормозит.

```jsonc
{
  "id": "AOI-0001", "crop_type": "озимая пшеница",
  "years": [2010, ..., 2025],
  "date":        ["2010-04-01", "2010-04-02", ...],  // суточная сетка, 1 апр — 30 окт
  "ndvi_obs":    [null, 0.31, null, ...],            // наблюдение; null = облако
  "ndvi_filled": [0.378, 0.391, ...],                // восстановленное, без пропусков
  "ndvi_smooth": [0.377, 0.390, ...],                // сглаженное, по нему считаются аномалии
  "clim_mean":   [0.432, 0.435, ...],                // климатнорма на этот день года
  "clim_std":    [0.177, 0.176, ...],                // её разброс -> коридор ±1σ
  "z":           [-0.31, -0.28, ...],                // (ndvi_smooth - clim_mean) / clim_std
  "status":      ["Штатное развитие", ...],
  "is_control_point": [false, ...],                  // точка, которую оценивало жюри
  "precip_30d":  [31.21, ...],                       // осадки за 30 дней, мм
  "temp_30d":    [9.91, ...]                         // средняя температура за 30 дней, °C
}
```

Ответ `/analyze` несёт **те же поля**, но списком объектов (`result.series`) —
это прямой вывод модели. Один адаптер на два источника пишется в десять строк,
напиши его сразу, иначе получишь два кода отрисовки графика.

### `anomalies.json` и `result.anomalies` — один формат

```jsonc
{"anon_polygon_id": "AOI-0005", "year": 2015,
 "start": "2015-04-01", "end": "2015-04-14", "days": 14,
 "z_min": -4.45, "z_mean": -2.90,
 "ndvi_mean": 0.085, "clim_mean": 0.375, "drop_vs_norm": -0.290,
 "severity": "Критическая аномалия", "crop_type": "озимая пшеница",
 "precip_30d": 12.4, "precip_30d_norm": 38.1, "temp_anom": 1.2,
 "cause": "дефицит осадков", "precip_ratio": 0.33,
 "comment": "человекочитаемое пояснение"}
```

`z_min` — глубина в сигмах, `drop_vs_norm` — она же в единицах NDVI.
`severity` два значения, `cause` пять: дефицит осадков, температурный стресс,
засуха (оба сразу), устойчивое угнетение без погодного сигнала, краткое
отклонение без погодного сигнала.

### `metrics.json`

```jsonc
{"truth": {"lightgbm": {"RMSE": 0.06421, "GapScore": 10.74, "R2": 0.913, ...},
           "линейная интерполяция": {"RMSE": 0.09695, ...}},
 "truth_by_group": [...],   // новый полигон / есть в обучении
 "truth_by_phase": [...],   // апр, май, июн, июл, авг, сен-окт
 "truth_by_crop":  [...], "truth_by_gap": [...],
 "validation": [...], "by_gap_length": [...], "anomaly_agreement": [...]}
```

`GapScore` — оценка жюри: `30 * max(0, 1 - RMSE / 0.10)`, максимум 30.

Пересобрать, если модель переобучат: `python build_data.py` из корня основного
репозитория.

## Грабли

Каждая стоила времени, выписаны не для красоты.

- **Не соединять линией через зиму.** В данных только 1 апреля — 30 октября.
  Между 30 октября и 1 апреля разрыв, иначе через зиму протянется прямая,
  которой не существует. Рисуй посезонно.
- **Ось Y фиксировать на [−0.2, 1.0].** Автомасштаб прыгает между полигонами,
  и графики становятся несравнимыми.
- **`ndvi_obs` разрежен на две трети.** Это облака, а не битые данные. Точками,
  пропуски не соединять.
- **Минимум 3 сезона в `/analyze`.** Климатнорма строится leave-one-year-out:
  на одном сезоне она пуста, ряд восстановится, а аномалий не найдётся вообще
  и молча. Бэкенд отклоняет меньшее, но и в UI не давай выбрать.
- **`z` считается от `ndvi_smooth`, не от `ndvi_filled`** — сглаженный ряд не
  даёт ложных срабатываний на одиночных выбросах.
- **`status` = "нет данных"** бывает в начале ряда: климатнормы там ещё нет.
- **Все тексты русские и приходят из данных** — не хардкодь списки, бери из
  `data/meta.json` и `GET /meta`.
- **20 полигонов из 78 без аномалий** — пустое состояние обязательно.
- **Ответ жирный:** 0.9 МБ на поле за 10 лет, полтора на 16. Не держи в
  состоянии несколько разборов сразу.
- **Задачи живут в памяти процесса.** Рестарт бэкенда — и `job_id` протух,
  `GET /analyze/{id}` вернёт 404. Обработай: предложи повторить, не показывай
  вечный спиннер. Результат хранится час.
- **Одно поле за раз.** Модель обучалась на данных, где часть признаков смотрит
  на соседние поля в ту же дату; для одиночной области они пусты, и точность
  чуть ниже эталонной. Это ожидаемо, а не поломка.
