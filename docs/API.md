# HTTP API

FastAPI поверх обученной модели. Модель поднимается один раз при старте и
держится в памяти: запрос — это пересчёт признаков и предсказание, без
переобучения.

```bash
cd backend && pip install -r requirements.txt
uvicorn serve:app --reload --port 8000
```

Машинное описание — `../openapi.json`, сгенерировано из приложения.
Интерактивная документация: http://localhost:8000/docs

Пять эндпоинтов:

| метод | путь | зачем |
|---|---|---|
| GET | `/health` | жив ли сервис, загрузилась ли модель |
| GET | `/meta` | лимиты, справочники, доступен ли Earth Engine |
| POST | `/analyze` | область на карте -> задача |
| GET | `/analyze/{job_id}` | статус и результат задачи |
| POST | `/predict` | готовые строки -> разбор, синхронно |

---

## `GET /health`

```json
{"status": "ok", "features": 106,
 "config": {"target": "raw", "clip": [-0.2, 1.0], "rounds": 40, "seed": 0, "n_features": 106}}
```

Первый вызов грузит модель с диска, пара секунд. Дальше мгновенно. Дёргай на
старте фронта, чтобы отличить «бэкенд не поднят» от «запрос упал».

## `GET /meta`

Всё, что нужно знать до первого запроса. **Строй UI по нему, не хардкодь.**

```json
{"region_box": {"min_lon": 38.3, "min_lat": 46.8, "max_lon": 41.3, "max_lat": 49.3},
 "crop_types": ["озимая пшеница", "зерновые", "подсолнечник", "пастбища/зерновые", "неизвестно"],
 "years": {"min": 2010, "max": 2025, "default": [2016, 2025], "min_span": 3},
 "max_area_ha": 5000.0,
 "gee_available": true,
 "typical_fetch_seconds": 60}
```

`region_box` — рамка, в которой модель обучена. Ограничь рисование ею.
`gee_available: false` — прячь карту, показывай демо-режим на `data/`.

## `POST /analyze` — область на карте

Выгрузка из Earth Engine занимает около минуты. Столько держать открытый
HTTP-запрос нельзя, поэтому эндпоинт ставит задачу и сразу отвечает.

### Запрос

```json
{"geometry": {"type": "Polygon",
              "coordinates": [[[39.8408, 48.0056], [39.8441, 48.0056],
                               [39.8441, 48.0079], [39.8408, 48.0079],
                               [39.8408, 48.0056]]]},
 "years": [2016, 2025],
 "crop_type": "озимая пшеница"}
```

- `geometry` — GeoJSON `Polygon` или `MultiPolygon` в WGS84. GeoJSON `Feature`
  тоже принимается: Leaflet.draw отдаёт именно его, разворачивать не надо.
- `years` — `[первый, последний]` разворачивается в диапазон; можно и полным
  списком. Минимум 3 сезона.
- `crop_type` — из `/meta`, необязательно. Точность с ним чуть выше.

Готовый пример — `samples/analyze_request.json`.

### Ответ

```json
{"job_id": "eb86dfe8354743999abdf2633d3289a8", "status": "queued",
 "area_ha": 6.2, "years": [2016, 2017, ..., 2025],
 "poll": "/analyze/eb86dfe8354743999abdf2633d3289a8",
 "expected_seconds": 80}
```

### Отказы

Все проверки — до постановки задачи, ответ мгновенный.

| код | когда | текст |
|---|---|---|
| 400 | не Polygon/MultiPolygon | `geometry: нужен GeoJSON Polygon или MultiPolygon` |
| 400 | меньше 3 сезонов | про leave-one-year-out и пустую климатнорму |
| 400 | площадь больше 5000 га | `обведи поле, а не район` |
| 400 | вне рамки региона | `за его пределами другие культуры и другая климатнорма` |
| 503 | Earth Engine не настроен | как настроить, плюс что данные в `data/` работают и без него |

**Проверяй те же условия на фронте.** Пользователь не должен узнавать о лимите
площади после того, как обвёл полрайона.

## `GET /analyze/{job_id}`

Опрашивать раз в 2–3 секунды.

```jsonc
// в работе
{"status": "running", "stage": "тянем спутники и погоду", "progress": 0.1,
 "area_ha": 6.2, "years": [2016, ..., 2025], "created": 1757000000.0}

// после выгрузки, до модели
{"status": "running", "stage": "считаем признаки и восстанавливаем ряд", "progress": 0.7,
 "fetch": {"days": 2130, "observed": 728, "coverage_%": 34.2,
           "by_sensor": {"S2": 396, "Landsat": 335, "MODIS": 130},
           "weather_filled_%": 100.0, "years": [...]}}

// готово
{"status": "done", "stage": "готово", "progress": 1.0, "result": { ... }}

// не получилось
{"status": "error", "progress": 1.0,
 "error": "за выбранной областью нет ни одного наблюдения. Обычно это вода, город или область вне покрытия — выбери пашню."}
```

`status` ∈ `queued | running | done | error`. `fetch` появляется на середине —
показывай его сразу, пользователю интересно, сколько наблюдений нашлось.

**404** — задача не найдена: истёк час хранения или бэкенд перезапускался.
Не спиннер, а предложение повторить.

### `result`

## `POST /predict` — готовые строки

Когда данные уже есть: загруженный CSV, свой источник. Синхронно, Earth Engine
не трогает.

```jsonc
{"rows": [{"anon_polygon_id": "AOI-0005", "date": "2010-04-01",
           "primary_ndvi": null, "landsat_ndvi": 0.31,
           "era5_temp_c": 8.6, "era5_precip_mm": 0.05,
           "crop_type": "озимая пшеница"}],
 "with_anomalies": true}
```

Обязательны только `anon_polygon_id` и `date`. Остальные колонки — любые из
схемы исходных данных, чем больше, тем лучше. `primary_ndvi` пустой там, где
надо восстановить; если колонки нет вообще, восстанавливается всё.

Ответ — то же, что `result` у `/analyze`, без `fetch` и `area_ha`.

Пример на 3195 строк: `samples/predict_request.json` и `predict_response.json`.

### Что подавать

1. **Суточную сетку, а не только даты съёмок.** Соседи, окна и погодные
   накопления считаются по сетке. Пропущенные дни — строками с пустым
   `primary_ndvi`, а не выброшенными.
2. **Всю историю, а не один сезон.** Климатнорма leave-one-year-out: на одном
   сезоне пуста, аномалий не будет вообще и молча.
3. **Несколько полигонов сразу лучше**, чем по одному: часть признаков смотрит
   на аномалию соседних полей в ту же дату.

Сезон — 1 апреля по 30 октября, 213 суток в году.

### Отказы

| код | когда |
|---|---|
| 400 | пустой `rows`; нет `anon_polygon_id` или `date` |
| 422 | тело не по схеме, стандартный формат FastAPI |
| 500 | упал инференс: `{"detail": "ошибка инференса: ..."}` |

### Производительность

Замерено: один полигон за 16 лет (3195 строк) — **0.8 с**, ответ 1.4 МБ.
Время растёт от числа строк, почти не зависит от числа полигонов. Первый
запрос после старта дольше на пару секунд — грузится модель.

CSV разбирай на фронте (papaparse или аналог) и шли JSON: отдельного эндпоинта
для файла нет.

## Вызовы

```bash
curl http://localhost:8000/meta

curl -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  --data-binary @samples/analyze_request.json

curl http://localhost:8000/analyze/<job_id>
```

```js
const {job_id} = await (await fetch(`${API}/analyze`, {
  method: "POST", headers: {"Content-Type": "application/json"},
  body: JSON.stringify({geometry, years: [2016, 2025], crop_type}),
})).json();

for (;;) {
  await new Promise(r => setTimeout(r, 2500));
  const job = await (await fetch(`${API}/analyze/${job_id}`)).json();
  setStage(job.stage, job.progress, job.fetch);
  if (job.status === "done")  return job.result;
  if (job.status === "error") throw new Error(job.error);
}
```

## Настройки окружения

| переменная | зачем |
|---|---|
| `GEE_PROJECT` | id Cloud-проекта Earth Engine |
| `GEE_SERVICE_ACCOUNT_KEY` | путь к JSON-ключу сервисного аккаунта (прод) |
| `NDVI_MODEL` | путь к модели, по умолчанию `artifacts/ndvi_model.pkl` |
| `NDVI_CORS` | разрешённые источники через запятую, по умолчанию `*` |

CORS открыт для всех, чтобы не ломать чужой дев-сервер. Сузить:
`NDVI_CORS=http://localhost:5173`.

## Ограничения, которые важно знать

- **Задачи живут в памяти процесса.** Не переживают рестарт, не работают на
  нескольких воркерах uvicorn. Для демо этого хватает, для прода нужен Redis —
  сделано осознанно, а не забыто.
- **Одно поле за раз.** Признаки, смотрящие на соседние поля, для одиночной
  области пусты — точность чуть ниже эталонных 0.064 RMSE.
- **Только Ростовская область.** Модель обучена на ней, климатнорма и культуры
  других регионов другие.
