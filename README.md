# NDVI Монитор — восстановление рядов вегетации и поиск аномалий

Спутники снимают поля, из снимков считается NDVI — индекс зелёности. Ряд
дырявый: облачность выбивает до двух третей суток. Решение восстанавливает
пропуски, по восстановленному ряду находит периоды угнетения вегетации и
объясняет их погодой.

Две точки запуска, как требует постановка:

* **веб-сервис** — пользователь указывает регион, выбирает готовый контур поля
  или рисует свой, данные собираются и анализируются автоматически;
* **batch-инференс** — принимает `private_features.csv`, отдаёт `submission.csv`
  для строк `is_synthetic_gap = True`.

## Результат на ответах организаторов

Организаторы выдали ground truth первого тестового набора. Модель, обученная
только на `train_dataset.csv`, на его 3112 скрытых точках:

| | наша модель | линейная интерполяция |
|---|---|---|
| **RMSE** | **0.06384** | 0.09695 |
| **GapScore** | **10.85 / 30** | 0.92 |
| MAE | 0.04003 | 0.06637 |
| R² | 0.914 | 0.802 |
| попаданий ±0.05 | 74.5 % | 52.5 % |

Разрез по обобщению: новые полигоны 0.0656, знакомые по train 0.0527. 85 %
контрольных точек приходится на поля, которых в обучении не было.

Полный разбор — [REPORT.md](REPORT.md).

## Быстрый старт: интерфейс без бэкенда

Демо-режим на 78 эталонных полях и календарь аномалий работают на статике из
`data/` — этого достаточно, чтобы пройти основные сценарии.

```bash
cd web && npm install && npm run dev
```

Открыть <http://localhost:5173>. Ключей и настроек не нужно: карта работает на
OpenStreetMap. **Требуется Node.js 18+** (проверено на 22.19).

## Полный запуск: веб-сервис с расчётом по карте

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r backend/requirements.txt
cp .env.example .env                              # заполнить GEE_PROJECT
uvicorn backend.serve:app --port 8000             # из корня репозитория
```

Проверка: `curl http://localhost:8000/health` → `{"status":"ok","features":107}`.

Фронтенд берёт адрес бэкенда из `web/.env` (`VITE_API_URL`, по умолчанию
`http://localhost:8000`). Если бэкенд не поднят, интерфейс не ломается: в
подвале меню загорается «Оффлайн режим».

## Batch-инференс: submission.csv

```bash
cd ml
python predict_submission.py \
    --train train_dataset.csv \
    --test  test_features.csv \
    --extra labeled_test1.csv \
    --rounds 20 --seeds 0,42,100 \
    --outdir artifacts
```

| | |
|---|---|
| вход | `test_features.csv` в схеме `private_features.csv` |
| выход | `ml/artifacts/submission.csv` — три колонки `anon_polygon_id,date,primary_ndvi_pred`, UTF-8, только строки `is_synthetic_gap = True` |
| побочно | `ndvi_model.pkl`, `anomalies.csv`, `reconstructed_series.csv`, `series_with_zscore.csv` |
| время | ~40 мин на 8 ядрах (3 сида LightGBM + CatBoost) |

Готовый сабмит уже лежит в `ml/artifacts/submission.csv` — 2323 строки.

**Если модель переобучать не нужно**, готовая лежит в
`ml/artifacts/ndvi_model.pkl` и подключается сама: и веб-сервис, и CLI берут
её по умолчанию. Отдельный шаг обучения для проверки решения не требуется.

Инференс по своему CSV без платформы:

```bash
python backend/infer.py --input polygon.csv --outdir out/
# out/series.csv — восстановленный ряд с z-score, out/anomalies.csv — периоды
```

## Источники и структура данных

**От организаторов.** Строка = один полигон в одну дату, ключ
`anon_polygon_id + date`.

| файл | что это |
|---|---|
| `ml/train_dataset.csv` | 99 955 строк, 39 полигонов, 2010–2024, `primary_ndvi` известен |
| `ml/test_features.csv` | текущий тест: 49 190 строк, 20 полигонов, 2323 контрольные точки |
| `ml/test1_features.csv` | первый тест: 57 185 строк, 78 полигонов, 3112 точек |
| `ml/private_test_ground_truth.csv` | ответы на первый тест |
| `ml/labeled_test1.csv` | первый тест, сшитый с ответами — идёт в обучение |

В контрольной строке (`is_synthetic_gap = True`) замаскировано всё, кроме
`anon_polygon_id`, `date`, `is_synthetic_gap`, `crop_type`. Отсюда главное
правило кода: **признаки считаются только по замаскированной копии**
(`ndvi_ml.data.mask_rows`), иначе утечка не воспроизведётся на приватном скоре.

**Собираются сервисом самостоятельно** через Google Earth Engine:

| данные | коллекция |
|---|---|
| Sentinel-2 SR | `COPERNICUS/S2_SR_HARMONIZED` |
| Landsat 5/7 | `LANDSAT/LT05/C02/T1_L2`, `LANDSAT/LE07/C02/T1_L2` |
| Landsat 8/9 | `LANDSAT/LC08/C02/T1_L2`, `LANDSAT/LC09/C02/T1_L2` |
| MODIS NDVI/EVI | `MODIS/061/MOD13Q1` |
| погода | `ECMWF/ERA5_LAND/DAILY_AGGR`, `ECMWF/ERA5_LAND/HOURLY` |
| контуры полей | OpenStreetMap Overpass API |

`primary_ndvi` собирается по приоритету S2 → Landsat → MODIS. Сезон
1 апреля — 30 октября, суточная сетка. Рецепт восстановлен из самих данных и
описан в `ml/data_collection/RECIPE.md`.

Скрипты сбора и предобработки:

```bash
cd ml
python data_collection/fetch_fields.py     # контуры полей из OSM
python data_collection/gee_collect.py      # спутники и погода из GEE
python build_training_set.py --out extra_all.csv   # сведение в схему организаторов
```

## Доступы к внешним API

Ключей в репозитории нет. Шаблон — `.env.example`, реальные значения в `.env`
(он в `.gitignore`).

**Google Earth Engine** — нужен только для расчёта произвольного поля по карте.
Без него `/meta` вернёт `"gee_available": false`, а демо-режим и batch-инференс
работают как есть.

```bash
pip install earthengine-api
earthengine authenticate
# в .env:  GEE_PROJECT=ваш-project-id
```

Регистрация проекта: <https://code.earthengine.google.com/register>. Для
деплоя — сервисный аккаунт с ролью Earth Engine Resource Viewer, путь к
JSON-ключу в `GEE_SERVICE_ACCOUNT_KEY`.

**Gemini** — опциональный ИИ-разбор полей. Ключ из
<https://aistudio.google.com/apikey> в `GEMINI_API_KEY`. Читает его только
бэкенд; без ключа `/meta` отдаёт `"ai_available": false` и панель не
показывается.

## Детекция аномалий

Порог по z-score относительно климатнормы, построенной leave-one-year-out:

| z | класс |
|---|---|
| z ≥ −1 | штатное развитие |
| −2 ≤ z < −1 | угнетение биомассы |
| z < −2 | критическая аномалия |

z считается по сглаженному ряду, а не по восстановленному напрямую — иначе
одиночные выбросы дают ложные срабатывания. Период засчитывается от 10 суток
подряд: короче — это облако или шум. Причина подбирается по ERA5: дефицит
осадков, жара, засуха (оба сразу) либо «погодой не объясняется» — последнее
указывает на агрооперацию или ошибку данных.

Где посмотреть:

* в интерфейсе — «Спутниковый анализ» после расчёта, либо «Оффлайн режим» →
  «Разбор» у любого поля, либо «Календарь аномалий» по всему региону;
* в файлах — `ml/artifacts/anomalies.csv` после `predict_submission.py`;
* из CLI — `python backend/infer.py --input polygon.csv --outdir out/`.

## Сценарии для проверки

Первые четыре проходятся без бэкенда и без ключей.

1. **Разбор поля.** «Оффлайн режим» → «Разбор» у любого поля. Точки наблюдений,
   восстановленная кривая, коридор климатнормы ±1σ, подсвеченные аномалии.
   Галочка «Погода» добавляет осадки и температуру на отдельные оси.
2. **Сравнение полей.** Второе поле накладывается на тот же график.
3. **Пустое состояние.** 20 полей из 78 без аномалий — фильтр это показывает.
4. **Календарь.** Теплокарта год × месяц, клик по ячейке раскрывает периоды.
5. **Работа с полигонами** (нужен бэкенд). «Найти поля» ищет сельхоз-контуры OSM
   в текущих границах карты; поле можно обвести вручную от 3 точек, вершины
   перетаскиваются, правый клик удаляет. «В закладки» сохраняет разбор целиком —
   закладка открывается без пересчёта. Периметры сохранённых полей лежат
   отдельным слоем, клик по полю открывает его карточку.
6. **Спутниковая подложка.** Переключатель «Схема / Спутник» в легенде.

## Работа с новыми регионами

Модель обучена на Ростовской области, её рамка показана на карте пунктиром.
Это **не запрет**: за пределами рамки выгрузка данных и восстановление ряда
работают так же, меняется достоверность — климатнорма и разбор причин
откалиброваны на регионе обучения. Расчёт разрешён везде, ответ `/analyze` и
интерфейс помечают такой запрос флагом `outside_region`.

Поиск контуров через Overpass работает в любой точке мира без ключей.
Ограничения: область поиска не больше 1° по стороне и не больше 120 контуров
за раз — публичный Overpass на бо́льших запросах отваливается по таймауту.

## Известные ограничения

* **Одно поле за раз.** Часть признаков смотрит на соседние поля в ту же дату;
  для одиночной области они пусты, и точность чуть ниже эталонной.
* **Минимум 3 сезона.** Климатнорма строится leave-one-year-out: на одном
  сезоне она пуста, ряд восстановится, а аномалии не найдутся.
* **Задачи живут в памяти процесса.** Рестарт бэкенда — и `job_id` протух.
  Результат хранится час.
* **Recall аномалий 66 %.** Треть реальных просадок классифицируется как
  штатное развитие. Порог по z — сознательно простое решение, разметки аномалий
  в тесте нет и обучать классификатор не на чем.
* **Ответ жирный:** 0.9 МБ на поле за 10 лет.
