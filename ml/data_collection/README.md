# Расширение датасета

78 полигонов — главное ограничение решения. Всё, что не про данные (гиперпараметры,
лоссы, ансамбли, чистка признаков), за ночь перебора дало ноль. Разброс качества
между фолдами — от 0.0620 до 0.0875 в зависимости от того, какие поля отложены:
так выглядит нехватка разнообразия, а не недоученная модель.

Постановка прямо разрешает дособирать данные из открытых источников и требует
только зафиксировать источники и параметры в README.

## Что здесь лежит

| файл | что делает |
|---|---|
| `RECIPE.md` | восстановленный из данных рецепт организаторов: коллекции, приоритет сенсоров, окно, формулы |
| `gee_rostov.py` | **основной сбор**: вся область целиком, прямая выгрузка на диск, резюмируемая |
| `fetch_fields.py` | контуры полей из OpenStreetMap через Overpass API |
| `gee_export.py` | выгрузка S2 / Landsat / MODIS / ERA5 из Google Earth Engine в схеме организаторов |
| `merge_external.py` | сводит выгрузку в суточную сетку и считает `primary_ndvi` по их приоритету |
| `validate_external.py` | сверяет распределения с данными организаторов — обязательный шаг перед обучением |

## Быстрый путь: gee_rostov.py

Одна команда собирает всю Ростовскую область и сводит результат в схему
организаторов:

```bash
python data_collection/gee_rostov.py --project <gee-project> --fields 500 --merge
```

Чем он отличается от `gee_collect.py` (тот остаётся запасным путём через Drive):

- **регион — вся область** по границе FAO GAUL, а не прямоугольник;
- **отбор идёт по тайлам параллельно**, квоты по пиковому NDVI раздаются в
  Python и по кругу между тайлами, поэтому поля разложены по всей территории,
  а не сидят в двух районах;
- **выгрузка прямыми запросами** `getDownloadURL` пулом потоков сразу в каталог
  на диске. Drive, ожидание задач и ручное скачивание не нужны: десятки минут
  вместо часов;
- **геометрия полей считается один раз** и кэшируется в `fields_b*.geojson` —
  в экспортных задачах цепочка отбора пересчитывалась заново на каждую задачу,
  это и была основная плата за время;
- **прогон резюмируемый**: готовый кусок пропускается, упавший режется пополам
  и повторяется. Ctrl+C и повторный запуск продолжают с места;
- **культура размечается** по ESA WorldCereal (озимые / яровые / кукуруза),
  а не ставится «неизвестно» всем полям.

Полезные флаги:

| флаг | зачем |
|---|---|
| `--select-only` | посмотреть отбор и сводку по пику NDVI, ничего не выгружая |
| `--reselect` | пересобрать отбор, игнорируя кэш |
| `--workers N` | параллельных запросов к GEE (по умолчанию 8) |
| `--block-mult 0.5` | мельче блоки, если куски падают по времени |
| `--batch 2` | вторая партия полей, не пересекается с первой |
| `--no-crops` | пропустить разметку культуры |

Выход — тот же формат файлов, что у `gee_collect.py`, поэтому без `--merge`
дальше работает обычный `python run_external.py --raw rostov_raw/`.

## Порядок через Drive (запасной путь)

```bash
# 1. контуры полей (Ростовская область по умолчанию)
python data_collection/fetch_fields.py --limit 500 --out fields.geojson

# 2. выгрузка из GEE — ставит задачи, идут часами
earthengine authenticate
python data_collection/gee_export.py --fields fields.geojson --years 2010-2025 \
    --scale 20 --project <твой-gee-проект>

# 3. когда задачи доедут — свести в схему организаторов
python data_collection/merge_external.py --raw exports/ --fields fields.geojson \
    --out external_train.csv

# 4. ОБЯЗАТЕЛЬНО: сверить распределения
python data_collection/validate_external.py --external external_train.csv \
    --reference train_dataset.csv

# 5. подмешать в обучение (в валидацию они не попадут — это гарантировано кодом)
python run_experiment.py --train train_dataset.csv --test private_features.csv \
    --rounds 15 --extra external_train.csv
```

## Почему шаг 4 нельзя пропускать

Полигоны организаторов анонимизированы — мы не знаем, где они, и не можем
сверить наш сбор построчно. Единственная доступная проверка — распределения:
частота наблюдений на полигон-сезон, сезонный ход NDVI, диапазоны значений.

Если наш `primary_ndvi` систематически отличается от их (другая маска облаков,
другая агрегация по контуру, другой набор миссий Landsat), то новые поля будут
тянуть модель в свою сторону и качество на их полигонах **упадёт**, хотя данных
станет больше. `validate_external.py` ловит именно это.

Финальная проверка всё равно одна: прогнать `run_experiment.py` с `--extra` и
без него. Валидация в обоих случаях идёт по полигонам организаторов, поэтому
числа сравнимы напрямую. Выросло — данные годные, упало — сбор чинить.

## Гарантия от протечки

`load_raw(..., extra_paths=[...])` помечает дособранные строки как
`source == "external"`, и все три сценария валидации исключают их из валидационных
фолдов. Проверено смоук-тестом: внешние строки попадают только в обучение.

## Что даст больше всего

1. **Число полей.** 78 → 400-500. Это основной рычаг.
2. **Разнообразие культур.** Сейчас 8578 из 15203 валидационных точек — озимая
   пшеница, и она же самая трудная (попаданий в ±0.05 всего 63% против 77% у
   зерновых). Отдельно добирать поля под неё.
3. **Тот же климат.** Собирать из того же региона: у полигонов организаторов
   корреляция температуры 0.99, это одна область. Точные ячейки ERA5 можно найти,
   сопоставив их `era5_temp_c` с сеткой ERA5-Land (шаг 0.1°) — ряд за 15 лет
   практически уникален для ячейки.

## Риски

- **Наш NDVI ≠ их NDVI.** Главный риск, лечится шагом 4 и весами при обучении.
- **OSM размечен неравномерно.** Часть полей отсутствует, часть — с устаревшими
  контурами. Альтернатива — ESA WorldCereal, там маска пашни, но без готовых
  контуров: их придётся выделять связными компонентами.
- **Культура неизвестна.** В OSM тег `crop` заполнен редко. Либо ставить
  «неизвестно» (модель это переживёт, культура — не главный признак), либо
  брать классы из WorldCereal.
- **Квоты GEE.** Пятьсот полигонов на 16 сезонов по четырём коллекциям — это
  сотни задач. Разбивать на партии по 50 полей.
