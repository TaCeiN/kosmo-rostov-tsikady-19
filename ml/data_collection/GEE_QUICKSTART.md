# Сбор полей через GEE: что запускать

Три команды. Между второй и третьей — ожидание, оно на серверах Google,
машину можно выключить.

## 0. Один раз

```bash
pip install earthengine-api
earthengine authenticate
```

Откроется браузер. Нужен Google-аккаунт с зарегистрированным Earth Engine и
Cloud-проектом — его id понадобится дальше как `--project`.

## 1. Проба: 3 поля, один год

```bash
python data_collection/gee_collect.py --project <project-id> --fields 3 --years 2024-2024 --dry-run
```

`--dry-run` ничего не выгружает, только считает отбор и печатает пиковый NDVI
отобранных участков. Ждать до пары минут.

**Что должно получиться:** участков 3, ячеек погоды 1–3, пиковый NDVI в районе
0.4–0.9. Если пик у всех около 0.3 — выборка села на залежь, пиши, поправлю
пороги. Если участков 0 — подними множитель кандидатов в `select_fields`.

## 2. Боевой сбор

```bash
python data_collection/gee_collect.py --project <project-id> --fields 300 --watch
```

65 задач (16 лет × 4 источника + паспорт). Скрипт ставит их сам и опрашивает
раз в минуту, печатая `готово N, в работе M, упало K`. Ctrl+C выходит из
слежения, но задачи продолжают считаться — состояние всегда видно на
https://code.earthengine.google.com/tasks

Часы, а не минуты. Выгрузка едет в Google Drive, папка `ndvi_external`.

**Про лимиты.** Тариф Community — 150 EECU-часов в месяц. 300 полей за 16 лет
в него укладываются с запасом; 800 — впритык. Если задачи начнут падать
с `User memory limit exceeded`, гони партиями:

```bash
python data_collection/gee_collect.py --project <project-id> --fields 300 --batch 3 --watch
```

`--batch` меняет и сид выборки, и префикс id (`EXT2-`, `EXT3-`), поэтому партии
не пересекаются по полям и не конфликтуют по именам. **Начинать с `--batch 2`:**
единица занята старым сбором по неверной рамке.

## 3. Обучение с новыми данными

Скачать папку `ndvi_external` из Drive, распаковать, и:

```bash
python run_external.py --raw ndvi_external/ --check
```

Дальше всё само: сведение в схему организаторов → сверка распределений →
замер на холдауте → финальная модель → `artifacts/submission.csv`.

`--check` добавляет замер «помогают ли новые поля» на половине B полигонов
test1 — единственном холдауте, который переживает раздачу ответов в обучение.
Стоит два лишних обучения (~15 мин), но без него ты не узнаешь, не утянул ли
сбор модель в свою сторону. Скрипт покажет ΔRMSE и спросит, продолжать ли.

Без проверки, сразу в бой:

```bash
python run_external.py --raw ndvi_external/
```

## Что выгружается

| файл | что внутри |
|---|---|
| `ndvi_fields_meta_b*.csv` | паспорт: id, ячейка погоды, чистота пашни, однородность, пик NDVI |
| `ndvi_s2_ГОД_b*.csv` | Sentinel-2: ndvi, evi, ndwi |
| `ndvi_landsat_ГОД_b*.csv` | Landsat 5/7/8/9 вместе |
| `ndvi_modis_ГОД_b*.csv` | MODIS MOD13Q1 |
| `ndvi_era5_ГОД_b*.csv` | погода **по ячейкам 0.1°**, не по полям |

Паспорт терять нельзя: ERA5 сшивается с полями только через `cell_id` из него.

## Если что-то не так

| симптом | что делать |
|---|---|
| `Please authorize access` | `earthengine authenticate` |
| `not signed up for Earth Engine` | зарегистрировать проект на earthengine.google.com |
| `User memory limit exceeded` | `--fields` вдвое меньше, добрать второй партией |
| `Computation timed out` | гнать по 4–5 лет: `--years 2017-2021`, потом `--years 2022-2025` |
| пустые CSV по S2 за 2010–2016 | норма, Sentinel-2 здесь начинается с 2017 |
| мало строк Landsat за 2012 | норма, между L5 и L8 работал только Landsat 7 |
| отобралось меньше полей, чем просил | три фильтра подряд съедают кандидатов; подними `numPoints` |

## Почему поля отбираются именно так

Три фильтра, каждый закрывает свою дыру (подробности — в комментариях
`gee_collect.py`):

1. **чистота пашни ≥ 95%** по ESA WorldCover — квадрат не должен залезать на
   дорогу, лесополосу или застройку;
2. **однородность, разброс NDVI ≤ 0.08** — маска пашни не отличает одно поле от
   двух соседних, а квадрат на границе даёт средний NDVI как смесь двух культур:
   кривую, которой в природе не существует;
3. **пиковый NDVI ≥ 0.40** — маска включает пастбища и залежь. У организаторов
   медиана пика 0.60, первая наша выборка дала 0.38, и сезонный ход разошёлся.

Рамка региона — `REGION_BOX` в `gee_collect.py`, продуктивная часть Ростовской
области. Первая версия уходила на юго-восток в сухую степь у границы с
Калмыкией, и NDVI там оказался на 0.10 ниже, чем у организаторов.
