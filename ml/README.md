## Установка и запуск

```bash
pip install -r requirements.txt

# основной сценарий: честный замер -> сшивка ответов -> финальная модель -> сабмит
./run_final.sh train_dataset.csv test1_features.csv \
    private_test_ground_truth.csv test_features.csv
```

Параметры: `ROUNDS` (замер, по умолчанию 15) и `FINAL_ROUNDS` (финальная модель, 40).
Больше раундов — лучше качество и дольше счёт, зависимость затухающая.

**Что где оказывается:**

| файл | зачем |
|---|---|
| `artifacts/submission.csv` | на платформу, колонка `primary_ndvi_pred` |
| `artifacts/ndvi_model.pkl` | модель для инференса и веб-сервиса |
| `reports_truth/truth_metrics.csv` | настоящие RMSE и GapScore |
| `artifacts/anomalies.csv` | найденные аномальные периоды |

Старый сценарий на синтетической валидации остался как `./run_all.sh` — он нужен,
когда сравниваешь методы между собой, а не меряешь итоговое качество.

Или по шагам, если нужно гонять что-то одно:

```bash
python run_experiment.py --train train_dataset.csv --test private_features.csv \
```

## Инференс: модель как сервис

Обученная модель сохраняется одним файлом и поднимается без переобучения.

```bash
# командная строка
python infer.py --model artifacts/ndvi_model.pkl --input polygon.csv --outdir out/

# HTTP-сервис для веб-интерфейса
pip install fastapi uvicorn
uvicorn serve:app --reload
# POST /predict {"rows": [...]} -> {"series": [...], "anomalies": [...], "summary": {...}}
# GET  /health
```

```python
from ndvi_ml.pipeline import NdviPipeline
pipe = NdviPipeline.load("artifacts/ndvi_model.pkl")
res = pipe.predict_frame(df)      # df в схеме исходных данных
res.filled                        # восстановленный NDVI по строкам
res.series                        # ряд с нормой, z-score и статусом
res.anomalies                     # периоды угнетения с интерпретацией
```

**Что подавать на вход.** Суточную сетку сезона, а не только даты наблюдений:
соседи, окна и погодные накопления считаются по ней. И всю историю полигона,
а не один сезон — климатнорма строится leave-one-year-out, на единственном
сезоне она пуста, и аномалии молча не найдутся. Несколько полигонов сразу —
лучше, чем по одному: пространственные признаки смотрят на соседние поля.

## Как это устроено

**Признаки (~85 штук).** Соседние наблюдения и расстояния до них, линейная интерполяция
и экстраполяции по локальному тренду, кривизна, скользящие окна NDVI, гармоники дня года,
климатнорма трёх уровней (полигон / культура / глобально) с leave-one-year-out,
перенос аномалии соседних дат, ближайшие значения S2/Landsat/MODIS и их разброс,
накопленные тепло и осадки, доля сухих и жарких дней. Плюс стекинг: предсказания
Savitzky-Golay, Whittaker и climatology+anomaly идут в модель как признаки — они же
дают ей 67% суммарного gain.

**Обучение.** Обучающие примеры — искусственные дырки: прячем 15% наблюдений сериями
по 1–4 подряд (так выбивает облачность), считаем признаки по замаскированной копии и
учимся только на спрятанных строках. Несколько раундов с разными сидами = аугментация.
Смысл в том, чтобы распределение признаков на обучении совпадало с тем, что модель
увидит на контрольных точках.

**Валидация.** Три сценария: `new_polygon` (GroupKFold по полигонам — главный),
`last_season` (знакомое поле, новый сезон) и `random` (оптимистичная оценка для сравнения).

**Задача 2.** По восстановленному и сглаженному ряду считается z-score относительно
климатнормы, ищутся связные периоды с z < −1 длиной от 10 дней, каждому приписывается
погодная версия причины по ERA5 (дефицит осадков, жара, оба, либо «погодой не объясняется»).

## Формат сабмита и метрика

`submission.csv` — ровно три колонки: `anon_polygon_id`, `date`,
**`primary_ndvi_pred`** (именно так, а не `primary_ndvi`), UTF-8, без пропусков
и дублей пары полигон+дата.

Оценка: `GapScore = round(30 * max(0, 1 − RMSE / 0.10), 2)`. Метрика линейна по
RMSE, порог 0.10 — качество простого baseline. Текущие 0.0745 дают **7.64 из 30**;
каждая тысячная RMSE стоит 0.3 балла.

## Что важно знать про данные

Полное описание — в `CLAUDE.md`. Коротко: в контрольных строках замаскировано всё,
кроме id, даты и культуры, поэтому все признаки считаются по замаскированной копии;
climatology считается leave-one-year-out; статистики сезона — leave-one-out по строке.

Отдельно: в разметке встречаются физически невозможные значения NDVI (вне [−1, 1]).
Их всего 3 на 7 222 валидационные точки, но они дают 19% суммарного MSE — то есть
разница в четвёртом знаке RMSE между двумя моделями может быть просто шумом от пары
битых строк. Сравнивать модели надёжнее по MAE и медианной ошибке.
