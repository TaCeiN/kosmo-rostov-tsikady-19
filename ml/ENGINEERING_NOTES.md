# Контекст проекта для Claude Code

Кейс Космохакатона: восстановление ряда NDVI (задача 1) и детекция аномалий (задача 2).
Этот файл — то, что нужно знать перед любой правкой. Данные устроены неочевидно,
и большинство «улучшений» ломается именно об это.

## Данные

Организаторы по ходу хакатона заменили тестовый набор и выдали ответы на первый.
Сейчас на руках четыре файла:

| файл | что это |
|---|---|
| `train_dataset.csv` | 99 955 строк, 39 полигонов, 2010–2024. Есть `ndvi_zscore` и `status`, которых в тестах нет |
| `test1_features.csv` | первый тест: 57 185 строк, 78 полигонов, 2010–2025, 3112 контрольных точек |
| `private_test_ground_truth.csv` | **ответы на первый тест**, все 3112 значений |
| `test2_features.csv` | новый тест: 49 190 строк, 20 полигонов, 2010–2024, 2323 контрольные точки |

Полигоны нового теста — те же 20, что в первом тесте были представлены только
сезоном 2025. Теперь дана их история 2010–2024. Пересечений строк между
наборами нет вообще, ни одного.

**Ответы на первый тест меняют две вещи.** Во-первых, появился честный замер:
`evaluate_truth.py` меряет ровно ту метрику, что и платформа, вместо синтетических
дырок. Во-вторых, эти 3112 значений становятся обучающими данными —
`prepare_labeled.py` сшивает их с признаками, и размеченная выборка растёт
с 30 520 до 64 437 наблюдений, то есть вдвое.

### Проверено на реальных ответах

Модель, обученная только на train (rounds=40), дала на скрытых точках первого теста:

| | значение |
|---|---|
| RMSE | **0.06384** |
| GapScore | **10.85 из 30** |
| MAE | 0.04003 |
| R² | 0.914 |
| попаданий ±0.05 | 74.5% |

Локальная валидация предсказывала 0.0745, то есть была пессимистична — но её
метрика `RMSE_clean` (без битых строк) давала 0.0651, что почти точно совпало
с реальностью. В ground truth битых значений нет: все лежат в [−0.02, 0.93].
**Ориентироваться надо на `RMSE_clean`, а не на `RMSE`.**

Устройство теста:

| группа | полигонов | строк | с NDVI | контрольных точек | период |
|---|---|---|---|---|---|
| знакомые (есть в train) | 39 | 6 876 | 2 520 | 464 | только сезон 2025 |
| новые (только в test) | 39 | 50 309 | 15 121 | 2 648 | 2010–2025 |

**85% скора — новые полигоны.** Валидация со случайным сплитом врёт в оптимистичную сторону.

### Что видно в контрольной строке

У строк `is_synthetic_gap = True` замаскировано ВСЁ, кроме `anon_polygon_id`,
`date`, `is_synthetic_gap`, `crop_type`: нет спутниковых индексов, нет ERA5,
нет `doy`/`year`, нет климатнормы. `doy` и `year` восстанавливаются из `date`.

Отсюда главное правило кода: **признаки считаются только по замаскированной копии**
(`data.mask_rows`). Любой признак, использующий колонки самой целевой строки, —
утечка, которая не воспроизведётся на приватном скоре.

Проверенные грабли, которые уже исправлены (не откатывать):

- `shift` при поиске соседей должен идти внутри группы `(полигон, год)`, иначе
  «сосед» приезжает из прошлого сезона и `gap_len` доходит до 5708 дней;
- статистики сезона и полигона считаются leave-one-out (`features._loo_stat`),
  иначе у видимых строк они включают собственный NDVI, а у скрытых нет — обучение
  расходится с инференсом;
- климатнорма считается leave-one-**year**-out, иначе норма подсматривает
  в тот самый сезон, который восстанавливаем;
- у всех baseline-методов есть цепочка фолбэков, чтобы они отвечали на всех
  строках: иначе метод, отказывающийся отвечать на трудных точках, выглядит лучше.

## Как обучается модель

Обучающие примеры — это тоже дырки. В каждом раунде прячем случайные 15% наблюдений
сериями по 1–4 подряд (как выбивает облачность), считаем признаки по замаскированной
копии и берём в обучение только спрятанные строки. Несколько раундов = аугментация.
Так распределение признаков на обучении совпадает с тем, что будет на контрольных точках.

`--rounds N` управляет числом раундов, `--folds N` — фолдами по полигонам.

## Команды

Основной сценарий — `./run_final.sh train.csv test1.csv truth.csv test2.csv`:
честный замер, сшивка ответов, финальная модель и сабмит.

По шагам:

```bash
# настоящие RMSE и GapScore на ответах организаторов
python evaluate_truth.py --train train_dataset.csv --test-features test1_features.csv \
    --truth private_test_ground_truth.csv --rounds 15

# ответы -> обучающие данные
python prepare_labeled.py --features test1_features.csv \
    --truth private_test_ground_truth.csv --out labeled_test1.csv

# финальная модель и сабмит на новый тест
python predict_submission.py --train train_dataset.csv --test test2_features.csv \
    --extra labeled_test1.csv --rounds 40 --outdir artifacts

# старая валидация на синтетических дырках (нужна для сравнения методов)
python run_experiment.py --train train_dataset.csv --test test2_features.csv \
    --folds 4 --rounds 15 --outdir reports
python predict_submission.py --train train_dataset.csv --test private_features.csv \
    --rounds 25 --outdir artifacts
python make_charts.py --reports reports --artifacts artifacts --outdir charts
python make_report.py
```

Или всё сразу: `./run_all.sh train_dataset.csv private_features.csv`
(параметры через `ROUNDS`, `FINAL_ROUNDS`, `FOLDS`, `METHODS`).

## Инференс

`ndvi_ml/pipeline.py` — обученная модель одним объектом: `NdviPipeline.save/load`,
`predict_frame(df)` возвращает восстановленный ряд, z-score и аномалии.
Поверх неё `infer.py` (CLI) и `serve.py` (FastAPI). Модель лежит в
`artifacts/ndvi_model.pkl`, пересоздаётся `predict_submission.py`.

На вход нужна вся история полигона суточной сеткой: климатнорма
leave-one-year-out, на одном сезоне она пуста и аномалии не находятся.

## Ночная лаборатория

`night/` — инфраструктура перебора. Смысл: пересчёт признаков занимает 90%
времени прогона, поэтому матрицы считаются один раз (`night/cache_folds.py`)
и складываются в `cache_*/`, а эксперименты (`night/run_batch.py` + пачки
`night/batch*.py`) работают по кэшу и занимают минуты. `night/blend.py` ищет
ансамбли по сохранённым предсказаниям без переобучения, `night/finalize_reports.py`
собирает `reports/` из результатов лаборатории.

Опции конфигурации в `night/lab.py`: параметры LightGBM, `target` (учить поправку
к сглаживателю), `drop_broken`, `weight`, `split_gap`, `drop_features` (абляции).

Итоги ночи и список тупиков — `reports/NIGHT_LOG.md`. Не переоткрывай их заново.

## Расширение датасета

`data_collection/` — рецепт организаторов, восстановленный из самих данных
(`RECIPE.md`), и скрипты сбора: OSM Overpass для контуров, GEE для спутников
и ERA5, сведение в их схему, сверка распределений.

Дособранные данные подключаются флагом `--extra external_train.csv` у
`run_experiment.py` и `predict_submission.py`. В валидацию они не попадают
никогда — `source == "external"` исключается во всех трёх сценариях.

Ключевое из рецепта: `primary_ndvi` = S2, иначе Landsat, иначе MODIS (проверено
на 2308 строках, где есть и S2 и Landsat — S2 побеждает всегда). Сезон
1 апреля — 30 октября, 213 суток. NDWI — формула Макфитерса через зелёный канал.
ERA5: среднесуточная температура, суточная сумма осадков.

## Формат сабмита

Колонка называется `primary_ndvi_pred`, не `primary_ndvi` (стр. 13 постановки).
Ровно три колонки, UTF-8, пара полигон+дата встречается один раз.

GapScore = round(30 * max(0, 1 − RMSE / 0.10), 2). Линеен по RMSE: каждая
тысячная RMSE стоит 0.3 балла из 30. При текущих 0.0745 это 7.64 балла.
